# Surge 家族包（Surge + Surfboard）

## 这是什么

- **哪个 APP**：
  - **Surge**：苹果手机/平板/Mac 上的老牌代理工具（付费）。
  - **Surfboard**：安卓上的代理工具，配置格式和 Surge 基本同源，这份配置可以直接导入使用（差异见文末）。
- **文件**：`Surge.conf` —— 一份完整配置，含分流分组、去广告规则、网速优化设置。
- **仓库链接**：`https://gcore.jsdelivr.net/gh/YiMing918/proxy-app-rules@main/proxy_clients_rules/surge/Surge.conf`
- **有什么用**：
  - 分流：不同网站/App 自动走不同地区的节点（AI 走美国、YouTube 走香港、国内直连）。
  - 去广告：按域名拦截广告请求，不用装证书就能生效；另可加秋风的 Surge 模块加强。
  - 网速优化：加密 DNS 防污染、测速参数调稳（细目见下面）。

## 怎么用（Surge，苹果）

### 1. 先导入你的节点订阅
Surge 里订阅是加在配置里的：主页 →「设置（齿轮）」→「代理服务器」→「订阅」→ 添加你的订阅链接。或者先导入本配置，再去同一位置把订阅加上。

### 2. 导入这份配置
1. 主页左上角点**当前配置的名字** →「下载配置」→ 粘贴 `Surge.conf` 的链接（或先把文件存到手机再选「导入配置」从文件选）。
2. 导入后在配置列表里**点一下这份配置**选中它 —— **不选中不生效**。

### 3. 选中分组（默认线路已预设好）
主页的「策略」区域能看到 🤖 AI服务、📺 YouTube 等分组，每个分组默认选中的就是下面表格里的线路，平时不用动；点分组可以临时改选。

### 4. 要不要装证书（MITM）
- **本配置不用装证书**：分流和域名去广告不解密流量，配置里 [MITM] 是空的。
- 只有装下面那种**改内容**的模块（如知乎助手、秋风模块的脚本部分）时才需要：Surge「设置 → MITM（HTTPS 解密）」→ 生成 CA → 安装描述文件 → iOS「设置 → 通用 → 关于本机 → 证书信任设置」打开信任 → 回 Surge 打开 MITM 开关。

### 5. 怎么验证已经生效
1. 主页打开 Surge 开关，节点能测出延迟。
2. 打开 ChatGPT 能用，且「🤖 AI服务」分组里默认勾的是「🇺🇸 美国」。
3. 开屏广告多的 App 里广告被跳过，或在 Surge 的请求日志里看到广告域名被 REJECT。

### 6. 以后怎么更新
- 配置：主页左上角点配置名 → 对这份配置选「更新」重新拉取。
- 远程规则集（blackmatrix7 广告表等）Surge 会自己定期更新，不用管。
- 订阅：设置 → 代理服务器 → 订阅 → 更新。

### 7. 常见问题
- **导入失败**：链接打不开/文件不全时换文件方式导入重试。
- **规则不生效**：先确认这份配置被选中；再确认主页出站模式是「规则判定」（全局代理/全局直连会绕过分流）。
- **节点不进组（地区组空的）**：分组按节点名地区词认人（香港/🇭🇰/HK 都认）；节点名不带地区信息的去「👋 手动选择」直接挑。
- **某个网站打不开**：「🛑 广告拦截」组临时改 DIRECT，能打开就是被误拦。

## 怎么用（Surfboard，安卓）
1. Surfboard 主页点右上角「+」或「导入配置」→ 选文件/粘贴链接导入 `Surge.conf`。
2. 导入后在配置列表里**点选这份配置**并启动，才算生效。
3. Surfboard 与 Surge 的差别：不支持 Surge 的脚本/模块体系（下面表格里的模块类在 Surfboard 上装不了），个别 Surge 专属参数会被忽略；分流、分组、去广告规则这三样核心功能一致可用。

## 两条硬规矩（全套包统一，写在分组表这里）

**规矩一：默认地区没节点，会自动顺位，不会让组空着。**
每个用途组的第一顺位只是「默认」，不是唯一。比如 YouTube 默认香港，但你的订阅里一个香港节点都没有时，这个组不会失效——它默认选的是「📺 YouTube·顺位」兜底链组（fallback 组），顺序是：香港 → 日本 → 新加坡 → 美国 → 台湾 → 韩国 → 其他各地区 → ♻️ 自动选择（压尾）。链上哪个地区有节点就用哪个，只要订阅里还有任何节点，这个组就有得用。其他用途组同理：先走自己的偏好地区（AI 美国打头、流媒体 新加坡→美国），再按 新加坡/美国/台湾/日本/香港/韩国 补位，最后压自动选择。
**但这只是默认行为，没有锁死**：点开任何用途组，所有地区组都列全了，随时能自己改选任何地区组或去「👋 手动选择」点具体节点。（Surfboard 同理。）

**规矩二：家宽节点只许手动，绝不自动。**
名字里带「家宽 / 住宅 / 家庭宽带 / Residential」的节点，只出现在「🏠 家宽节点」这一个组里（纯手动选）。所有自动组的筛选正则都把家宽词剔除了，自动选择、故障转移、负载均衡、每个地区组里都不会有家宽节点，连「👋 手动选择」里都不放（故意的，不是漏了）。
原因：免费家宽上一秒能用、下一秒超时，太不稳定，混进自动组会把测速和自动切换全带乱。需要家宽时，自己去「🏠 家宽节点」里点开用。
（注：FlClash v3.4 原稿里家宽是留在各组当额外入口的；这一条是站长后来定的新规矩，移植版以新规矩为准。）

## 网速优化做了什么

- **加密 DNS（DoH）**：encrypted-dns-server 用阿里 + 腾讯 DoH，解析快、防污染；普通 DNS 作兜底。
- **简单主机名排除**（exclude-simple-hostnames）：局域网里的简单名字（如打印机、NAS）不绕代理处理，直达更快。
- **fake-ip 兼容名单**（always-real-ip）：微软检测、游戏联机、语音、时间同步等域名返回真实 IP，不被假 IP 弄坏。
- **测速容差 50 毫秒 + 超时 3 秒**（test-timeout）：不为小抖动频繁跳线；坏节点 3 秒放弃。
- **测速地址统一用 Cloudflare 的 204 地址**（internet-test-url / proxy-test-url）：和 FlClash 版同口径。
- **关掉 IPv6**（ipv6 = false）：和 FlClash 版一致，避开 IPv6 绕路与泄漏。

## 与 FlClash 版的差别

- **地区组里不能逐个挑节点**：和 Surge 的分组语法有关——地区组直接就是自动测速组（FlClash 版是「自动组+全部节点」两层）。想指定节点去「👋 手动选择」。
- **倍率分组是近似**：靠正则认「0.5x」「倍率2」这类写法，写法太野的节点名可能认不全。
- **没有 UnBan 白名单表**：改用 blackmatrix7 广告表（自家做了防误杀），效果接近。
- **节点名同时带两个地区词时**可能同时进两个组，影响很小。
- **Surfboard**：模块/脚本体系不支持、个别参数被忽略（见上文），核心分流一致。
