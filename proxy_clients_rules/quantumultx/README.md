# Quantumult X（圈 X / QX）包

## 这是什么

- **哪个 APP**：Quantumult X，俗称「圈 X」「QX」，苹果手机/平板上的代理工具（App Store 付费下载）。
- **文件**：`QuantumultX.conf` —— 一份完整配置，含分流策略组（按节点名自动分地区）、远程分流规则、去广告分流 + 去广告重写。
- **仓库链接**：`https://gcore.jsdelivr.net/gh/YiMing918/proxy-app-rules@main/proxy_clients_rules/quantumultx/QuantumultX.conf`
- **有什么用**：
  - 分流：不同网站/App 自动走不同地区的节点（AI 走美国、YouTube 走香港、国内直连），不用手动切。
  - 去广告：两层——域名分流拦截（不用证书）+ AllInOne 重写（改 App 内容，要装证书才工作，不装也不报错）。
  - 网速优化：加密 DNS 防污染、测速只测在用的组、容差调稳（细目见下面）。

## 怎么用（一步一步）

### 1. 先导入你的节点订阅
1. 打开圈 X，底部点「设置」→ 找到「节点」一栏 →「引用（订阅）」。
2. 点右上角「+」，把订阅链接粘进去，备注随便写，保存后等节点刷出来。
   （也可以改配置文件 `[server_remote]` 段里那行示例：去掉行首 `#`、把链接换成你的，再导入配置。）

### 2. 导入这份配置
1. 把 `QuantumultX.conf` 下载到手机，或复制它的链接。
2. 圈 X「设置」→ 最下面「下载配置」→ 粘贴链接/选文件 → 确认替换。
3. 替换完回到主页，**把顶部的总开关打开**——配置导入了但总开关没开，等于没生效。

### 3. 选中分组（默认线路已预设好）
1. 主页能看到各策略组（🤖 AI服务、📺 YouTube 等），每个组的第一位就是默认线路（见下面表格）。
2. 想换线路：点进分组，选另一个成员即可。
3. 「🚀 节点选择」保持「♻️ 自动选择」即可。

### 4. 装证书（MITM）——只有重写去广告需要
本配置的**分流和域名去广告不用证书**。只有 [rewrite_remote] 里那份 AllInOne 重写（深度去广告）需要：
1. 圈 X「设置」→「MitM」→「生成 CA 证书」→「安装证书」，按提示装描述文件。
2. 去 iOS「设置 → 通用 → 关于本机 → 证书信任设置」，把圈 X 的证书打开信任。
3. 回圈 X「设置 → MitM」，把「MitM」开关打开。
不装证书时重写那部分自动不工作，不影响其他功能，也不会报错。

### 5. 怎么验证已经生效
1. 主页点节点测速，能出延迟数字。
2. 打开 ChatGPT 能正常用；在主页「🤖 AI服务」组里看默认选中的是「🇺🇸 美国」组，就是 AI 分流生效。
3. 打开开屏广告多的 App 看广告是否被跳过；圈 X 的「网络活动」里能看到广告域名走了 reject。

### 6. 以后怎么更新
- 远程分流规则和重写：配置里写了每 86400 秒（一天）自动更新，圈 X 会自己拉，不用你管；想立刻更新，在「设置 → 分流/重写」的引用页手动下拉刷新。
- 配置本身：重新走一遍「下载配置」即可。
- 订阅：在节点引用页下拉刷新。

### 7. 常见问题
- **导入失败**：链接打不开或文件不全时失败，换个方式（先下文件再导入）重试。
- **规则不生效**：先查主页总开关开没开；再查主页模式是不是「规则分流」（全局代理会绕过分流）。
- **节点不进组（地区组是空的）**：分组按节点名里的地区词认人（香港/🇭🇰/HK 都认）。节点名不带地区信息的认不出来，去「👋 手动选择」直接挑。
- **prefer-doh3 报错**：那是 QX 1.6.0 才有的开关，旧版删掉 `[dns]` 里那一行即可。
- **某个网站打不开**：把「🛑 广告拦截」组临时改成 direct，能打开就是被误拦了。

## 两条硬规矩（全套包统一，写在分组表这里）

**规矩一：默认地区没节点，会自动顺位，不会让组空着。**
每个用途组的第一顺位只是「默认」，不是唯一。比如 YouTube 默认香港，但你的订阅里一个香港节点都没有时，这个组不会失效——它默认选的是「📺 YouTube·顺位」兜底链组（圈 X 的 available 组：按顺序用第一个可用的），顺序是：香港 → 日本 → 新加坡 → 美国 → 台湾 → 韩国 → 其他各地区 → ♻️ 自动选择（压尾）。链上哪个地区有节点就用哪个，只要订阅里还有任何节点，这个组就有得用。其他用途组同理：先走自己的偏好地区（AI 美国打头、流媒体 新加坡→美国），再按 新加坡/美国/台湾/日本/香港/韩国 补位，最后压自动选择。
**但这只是默认行为，没有锁死**：点开任何用途组，所有地区组都列全了，随时能自己改选任何地区组或具体节点。

**规矩二：家宽节点只许手动，绝不自动。**
名字里带「家宽 / 住宅 / 家庭宽带 / Residential」的节点，只出现在「🏠 家宽节点」这一个组里（纯手动选）。所有自动组的节点正则都把家宽词剔除了，所以自动选择、故障转移、负载均衡、每个地区组里都不会有家宽节点，连「👋 手动选择」里都不放（故意的，不是漏了）。
原因：免费家宽上一秒能用、下一秒超时，太不稳定，混进自动组会把测速和自动切换全带乱。需要家宽时，自己去「🏠 家宽节点」里点开用。
（注：FlClash v3.4 原稿里家宽是留在各组当额外入口的；这一条是站长后来定的新规矩，移植版以新规矩为准。）

## 网速优化做了什么

- **测速只测在用的组**（alive-checking=false）：没在用的自动组不偷偷测速——这正是 FlClash 版 lazy（懒测速）的等价做法，省额度又省电。
- **测速间隔 600 秒 + 容差 50 毫秒**：和 FlClash 版一模一样，不频繁换线、不烧额度。
- **加密 DNS（DoH）防污染**：用阿里 DoH 解析（圈 X 只认第一条 doh-server，所以只放一条最快的）；QX 1.6.0+ 还开了优先 DoH3，解析延迟更低。
- **DNS 排除名单**（dns_exclusion_list）：联机游戏、语音、时间同步、微软检测这些域名不走假 IP 解析，不会被弄坏。
- **服务器测速地址换成 Cloudflare 的 204 地址**（server_check_url）：和 FlClash 版同一个测速地址，测出来的延迟口径一致；超时 3 秒，坏节点不拖后腿。
- **节点不支持 UDP 就拒绝**（fallback_udp_policy = reject）：防 UDP 绕过代理。
- **关掉 IPv6 解析**（no-ipv6）：和 FlClash 版一致，避开 IPv6 绕路与泄漏。
- **资源解析器已预置**（KOP-XIAO 的 QuantumultX 解析器，长期维护）：订阅里带特殊格式的节点也能被正确解析进来，不用另外找。

## 与 FlClash 版的差别

- **故障转移组没有「检查间隔」参数**：圈 X 的 available 类型没有 interval 设置，它是连接失败时即时顺延到下一个节点，效果一样甚至更及时，只是参数没法写。
- **DNS 分流是近似的**：FlClash 版国外域名走国外 DoH、国内走国内 DoH；圈 X 统一走一条 DoH（防污染没问题，个别 CDN 定位可能略差）。
- **倍率分组是近似**：靠正则认「0.5x」「倍率2」这类写法，写法太野的节点名可能认不全。
- **节点名同时带两个地区词时**可能同时进两个组（FlClash 版只进先认到的一个），影响很小。
- **去广告来源不同**：FlClash 版是 ACL4SSR 规则集；圈 X 版是 blackmatrix7 广告分流 + 秋风分流 + AllInOne 重写，层数更多。
